## 问题与修复位置

- 首屏只恢复了语言标记，实际文字要等外部模块下载：`src/lib/first-paint.mjs` 在 head 内联运行，解析期间处理新增节点及文本，提前恢复界面文案、日期、元信息和文章网址筛选状态。解析结束即停止，由功能模块接管；不隐藏整个页面、不加等待定时器。
- 首页有两套语言脚本：`src/lib/evidence-copy.mjs` 只读取旧字典的静态字符串，构建时补双语属性；`public/workspace.js` 统一负责切换，旧脚本不再下载执行。原始项目/经历文案和修改位置保留。
- 桌面顶栏被延迟出现的按钮挤动：`public/workspace.css` 使用三列居中布局，仅顶栏的增强按钮隐藏时保留位置；根节点预留滚动条空间，避免长页面解析到一半时再轻移几像素。移动端仍为两行。
- 文章筛选区延迟出现：`src/pages/writing/index.astro` 初始保留布局但暂不可操作，恢复 URL 并绑定行为后启用；无 JavaScript 时隐藏筛选区，全部文章依然能阅读。增强脚本位于文档内的 `body-end` 插槽。
- 远程反馈短暂黑屏、过渡不可见：新页正文尚未解析就进入快照，旧正文淡出但没有新正文淡入。`BaseLayout.astro` 的 `rel="expect" blocking="render"` 等待主内容后隐藏标记，确保 main 已完整解析；`workspace.css` 保留旧 root/main 画面，并让新画面约 600ms 单向淡入。新正文及顶栏快照填充当前主题背景，避免透明空白区域残留旧文字。不使用模糊或全屏加载遮罩，顶栏不位移，快照不阻挡点击；减少动态效果时关闭。
- 外部样式到达较晚时，跨页过渡没有创建：`BaseLayout.astro` 的 `page-transition-policy` 在 head 内联声明开启规则及减少动态效果规则，不再等待外部 CSS 才开启。用户已在远程 Chrome 中确认正文动画实际播放，并认可 600ms 效果；临时诊断入口、面板和脚本已移除，普通访问直接使用验收后的效果。

文章内容、网址、来源快照、自动同步工作流、Giscus 文章关联键与 About 留言板键均未更改。

### 未创建过渡：关键开关内联

用户确认 `cf2ohisft` 中 Chrome 顶栏 Writing→About 真正跨页后仍显示“本次未触发过渡”。面板该状态意味着已收到 pagereveal，但没有 viewTransition 对象；延长动画时长不解决创建条件问题。

发现 [Chromium 问题 417115917](https://issues.chromium.org/issues/417115917)：完整 HTML 很快到齐、外部 CSS 尚未完成时，渲染阻塞可能过早结束，导致部分导航不创建过渡。这与现象相近，属于待验证的原因，不是已经确认的远程根因。

`BaseLayout.astro` 将 auto 及减少动态效果 none 两条开关放在 head 最早阶段的 `style is:inline#page-transition-policy`，不再只依赖外部 workspace.css 下载。不换路由器、不加加载遮罩、不改导航与文章行为。面板额外报告该内联规则是否被 CSSOM 识别；“已识别”不等同于实际播放。

本地另启临时对照服务：完整 HTML 立即发送，所有外部 CSS 延迟 800ms，禁止缓存。去掉内联策略的对照路径在首页→About、About→Writing 两次跨页均报未触发；保留内联策略的对应两次均捕获正文入场，完成后记录 600ms。临时服务只修改测试响应、不修改网站文章或资源。该结果支持加载时序假设，不能外推为所有环境均已修复。

随后用户在远程 Chrome 跨页检查中报告 “Content fade played · 600ms”，内联开关也已识别，并明确确认实际效果正常。至此，远程验收不再只依赖本机结果或“开关已识别”的提示；仍未覆盖所有浏览器及真实手机。
